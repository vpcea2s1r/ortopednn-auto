# Еженедельное ревью сайта на ошибки

## Назначение

Раз в неделю проверять live-сайт (ortopednn.ru) на технические ошибки, которые не видны в обычном деплое, но бьют по индексации и позициям. Это правило-чекап, а не разовый аудит: фильтр Яндекса (SQI 0, 51/267 страниц в индексе) требует постоянного контроля.

## Периодичность и триггер

- **Каждую неделю** — полный прогон по чеклисту ниже (можно автоматически по расписанию или вручную).
- **После каждого деплоя** — быстрая проверка раздела «Битые ссылки» и «Статусы страниц».
- **При подозрении на падение позиций** — внеочередной прогон + сверка с GSC.

## Чеклист ревью

### 1. Статусы всех страниц (200/404/redirect)

Скрипт: `C:\Users\user\AppData\Local\Temp\opencode\audit.mjs` — берёт sitemap-0.xml, прогоняет все URL, пишет `audit_results.json`.

Проверять:
- Все URL из sitemap = **200**, без 3xx-редиректов.
- Нет страниц с `status >= 400` (кроме сознательно удалённых, см. правило 10 AGENTS.md — запрет удаления страниц с трафиком).
- Медленных страниц нет (в скрипте фильтр `duration > 3000`).

### 2. Битые внутренние ссылки

Скрипт: `C:\Users\user\AppData\Local\Temp\opencode\checklinks.mjs` — собирает все `href` со всех страниц sitemap и проверяет каждый (12 потоков, ~5–7 мин).

Проверять:
- Ни одного `status >= 400`.
- **Ложные срабатывания, которые НЕ являются ошибками**:
  - `/blog/${o}/`, `/blog/${i}/` — template literal в JS глоссария (`src/scripts/glossary-tooltip.ts:25`), ловятся как `href` из бандла. Это код, не ссылка.
  - `/articles/*` — признак битой ссылки в статье (правильный путь `/blog/*`), чинить обязательно.

### 3. canonical и meta

- canonical на каждой странице (regex ищет `rel=canonical` в любом порядке атрибутов — у сайта `href` стоит ДО `rel`).
- canonical == собственный URL страницы (нет дублей/указания на другую).
- title и description не пустые.

### 4. Кодировка контента

При добавлении/правке статей с кириллицей:
- `[System.Text.Encoding]::UTF8.GetString($bytes)` должен содержать кодовые точки `[\u0400-\u04FF]`.
- Отсутствие mojibake `[\u2500-\u25FF]` (признак двойного кодирования CP866).
- Размер файла не вдвое меньше ожидаемого.
- Перед push: `.\scripts\encoding-verify.ps1`.

### 5. Скорость

- TTFB по главной и топ-страницам: `< 1s` в норме (по замерам 2026-08-08: 60–390 мс).
- Страницы — статический SSG, раздувание HTML не должно превышать ~50–60 KB.

### 6. Индексация (еженедельно, если доступно)

- GSC: количество проиндексированных страниц, 404/soft-404 с impressions > 0 (`responseFilter=PAGE_NOT_FOUND`/`SOFT_404`).
- Yandex.Webmaster: число страниц в поиске, исключённые, SQI.
- Если в GSC есть 404-страницы с трафиком — восстановить или поставить 301 (правило 10 AGENTS.md).

## Шаги после находки ошибок

1. Исправить в коде (например, битую ссылку `/articles/*` → `/blog/*`).
2. `npm run build` — build должен пройти без ошибок.
3. Проверить в `dist/` что фикс срендерился.
4. Коммит + push (описательный message, например `fix: repair 3 internal links`).
5. Обновить log.md в wiki.
