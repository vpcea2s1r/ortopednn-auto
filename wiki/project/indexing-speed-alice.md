# Скорость индексации в Яндексе и AI-видимость (Алиса AI)

**Источник:** https://habr.com/ru/articles/1065514/ — «Как быстро загнать страницу в индекс Яндекса — и почему для Алисы AI этого мало» (Игорь Новиков, ig_novvv, 2026).

## Описание

Методика ускорения попадания страниц в индекс Яндекса и оценка AI-видимости. Ключевой тезис: индексация — необходимое, но не достаточное условие попадания в ответы Алисы AI.

## Основные выводы

1. **Алиса AI строит ответ из проиндексированных страниц.** Алиса анализирует запрос, обращается к поиску Яндекса, использует его результаты и делит ответ на смысловые блоки. Источники отбираются из страниц, стоящих высоко в обычной выдаче. Непроиндексированной страницы в ответе Алисы физически нет.

2. **Отбор источников Алиса ведёт по ЭПОС** (экспертность, полезность, оригинальность, содержательность) — официальный аналог E-E-A-T у Яндекса (https://yandex.ru/support/webmaster/ru/epos). Индексация — предварительное условие, не гарантия: страница может попасть в базу за день и не появиться в ответе, если не проходит по ЭПОС.

3. **Кейс:** лендинг провисел в очереди переобхода 4 дня. ChatGPT процитировал его в первый день (скачивает напрямую). В ответе Алисы страница появилась только после переиндексации — канал Алисы завязан на индекс Яндекса, а не на прямой обход.

4. **Одна страница может закрыть несколько смысловых блоков ответа Алисы** — число ссылок на неё в ответе может превышать число ссылок на обычной странице выдачи.

## 4 инструмента ускорения индексации

| Инструмент | Роль | Горизонт |
|-----------|------|---------|
| **Переобход страниц** (Вебмастер → Индексирование → Переобход) | Точечная срочность для десятка URL | ≤ 3 дней, обычно быстрее |
| **IndexNow** | Мгновенная реакция — сайт сам уведомляет робота через HTTP | Часы |
| **Sitemap.xml** | Фон — снижает риск выпадения страниц из внимания при плановом обходе | Не ускоряет отдельную страницу |
| **Обход по счётчику Метрики** | Подстраховка — счётчик, привязанный к подтверждённому сайту, становится источником URL | Фон |

## Последовательность для новой страницы

1. Опубликовали → проверить 200-й код, не закрыта ли в robots.txt/метатеге (кейс: 3 дня потеряны из-за забытого `Disallow`).
2. Отправить **IndexNow сразу после публикации** (из CI/CD или плагина CMS).
3. Добавить URL в sitemap.xml, убедиться, что файл обновляется автоматически.
4. Срочная страница — дополнительно внести в «Переобход страниц».
5. Через 1–2 дня проверить статус: «В очереди» → «Заявка обработана» или «Ошибка».
6. Через 1–2 недели проверить присутствие в поиске, добавить важные страницы в мониторинг.

## IndexNow — детали

- Код **202** при новом ключе — не ошибка, ключ проверяется асинхронно. Повторная отправка с тем же ключом ничего не ускоряет.
- `urlList` — до 10 000 адресов за запрос.
- Ключ — 8–128 символов латиницы, цифр, дефиса; `keyLocation` нужен, только если файл ключа не в корне.
- Лимит переобхода общий на домен и поддомены — приоритет для срочных URL закладывать заранее.

```bash
curl -X POST "https://yandex.com/indexnow" \
  -H "Content-Type: application/json; charset=utf-8" \
  -d '{
    "host": "example.ru",
    "key": "EdD8dkmdNLlxREi2LkhJjYOH2kyQbJqM3cBKT5fX",
    "keyLocation": "https://example.ru/EdD8dkmdNLlxREi2LkhJjYOH2kyQbJqM3cBKT5fX.txt",
    "urlList": ["https://example.ru/novaya-stranica"]
  }'
```

## Замер отдачи (Метрика)

- Индексация отвечает на вопрос «есть ли страница в базе», Метрика — «что после попадания живого человека».
- **Сегмент AI Traffic** в Метрике: собирается вручную условием по источнику визита (готовой кнопки в интерфейсе нет). Показывает переходы из ссылок, которые Алиса и другие ассистенты показывают под ответом.
- Страницы начинают появляться в AI Traffic на 2–4 неделе после публикации — ИИ-сервисам нужно время на повторное сканирование и переоценку.
- Резкий рост отказов на новой странице — сигнал доработать контент.

## Итог

- Переобход/IndexNow/sitemap управляют **скоростью** попадания в базу.
- Позиции и цитирование в Алисе решает **содержание** против ЭПОС и конкурентов в топ-10.
- Последовательность можно повесить на скрипт публикации — она одинакова для статей и карточек товаров.

## Применимость к ortopednn.ru

- **Реализовано (2026-08-01):** IndexNow в `.github/workflows/github-pages.yml` — при каждом деплое шлёт все URL из `dist/sitemap-0.xml` (224 шт.) на `https://api.indexnow.org/indexnow` с корректным ключом.
- **Найденный баг:** в workflow использовался ключ `f6a8c2d1e9b4a7c3f5e8d2b1a4c7f9e0`, который НЕ совпадал с файлом ключа в public (`db2a3c9dfc354341aa8294c9915624ec.txt`) — IndexNow-запросы были невалидны. Исправлено: ключ взят из файла, добавлен `keyLocation`.
- **Раньше** отправлялась только главная `https://ortopednn.ru/` — теперь весь sitemap, включая новые статьи (мосты, пародонтология).
- Публикация статей идёт через GitHub Actions (rebuild + push) — IndexNow теперь срабатывает автоматически на каждую новую статью.
- Осталось вручную: настройка сегмента «AI Traffic» в Метрике (статья 1058796), переобход срочных URL в Вебмастере при необходимости.
