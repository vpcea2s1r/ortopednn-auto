# Humanizer-ru — очеловечивание текста (v3.0.0)

Скилл для редактирования русскоязычного текста со следами работы ИИ. Цель — сделать текст естественным, не искажая смысла. v3.0.0 добавляет AI-tell score (0–100), расширяет каталог с 29 до 53 паттернов и вводит обязательный цикл самопроверки.

## Когда применять
- Текст на русском выглядит механическим, сухим или шаблонным
- Нужно проверить текст, сгенерированный другой нейросетью
- Пользователь просит «очеловечить», «переписать», «убрать следы ИИ»
- Текст готовится к публикации (статья, пост, письмо, документ)
- В тексте видны однозначные маркеры копирования из чат-бота

## Когда не применять
- Текст не на русском языке
- Исходный код, конфигурационные файлы, технические логи
- Юридические документы, нормативные акты, договоры
- Художественная проза, поэзия, литературные эссе

## Дерево решений
```
Получили текст
  ↓
Это русский? — нет → отказ
  ↓ да
Жанр? — код / конфиг → отказ
       — договор / нормативный акт → только #29-38 (стиль/разметка), не трогать #8 канцелярит
       — художка / поэзия → не применять #16 правило трёх, #29 длинное тире
       — публицистика / маркетинг / блог → полный набор
  ↓
Прогнать regex по chatbot-artifacts (см. references/chatbot-artifacts.md)
  ↓
Найден хоть один однозначный маркер? — да → удалить, затем полный прогон
  ↓ нет
Сосчитать мягкие признаки по категориям
  ↓
Вычислить AI-tell score (см. рубрику ниже)
  ↓
Score 0–20 → текст вероятно человеческий, не править
Score 21–40 → выборочно править критические (🔴), перепроверить
Score 41+    → переписать целиком с сохранением фактов, затем self-audit loop
```

## Главное правило
**Ни один отдельный мягкий признак не даёт достаточного основания для вердикта «текст написан ИИ».** Оценка — всегда по кластерам: 1–2 совпадения бывают у людей, 5+ в одном абзаце — почти всегда ИИ.

## Пять ключевых принципов правки
1. **Удалять мусор.** Убирать вводные фразы-пустышки и слова-костыли.
2. **Ломать шаблоны.** Избегать парных сравнений, драматических списков, риторических подводок.
3. **Менять ритм.** Чередовать длину предложений. Два пункта лучше трёх. Разнообразить концовки абзацев.
4. **Доверять читателю.** Констатировать факты прямо. Избегать разжёвывания и оправданий.
5. **Никаких слоганов.** Если фраза звучит как пафосный слоган — переписать.

## AI-tell score (0–100)

Числовая плотность машинных признаков. Ниже — человечнее.

| Диапазон | Вердикт | Что значит |
|----------|---------|------------|
| 0–20 | Чистый | Читается как написанный конкретным человеком |
| 21–40 | Почти человеческий | 1–2 мелких признака, легко почистить |
| 41–60 | Смешанный | Половина ИИ, половина человек; вероятна частичная правка |
| 61–80 | Близок к ИИ | Множественные структурные признаки |
| 81–100 | Чистый ИИ | Целиком вывод чат-бота без правок |

**Формула (оценочная):** `score = 4 × patterns_hit + 25 × (1 − burstiness) + 15 × (vocab_ratio)`, где:
- `patterns_hit` — число сработавших паттернов из каталога ниже;
- `burstiness` — вариативность длины предложений (нормализовано 0–1; одинаковые длины → низкая);
- `vocab_ratio` — доля машинной лексики (#13, #12) в тексте.

Модель склонна завышать оценку собственного текста в той же сессии. Трактуй score как сигнал, не приговор: реальный гейт — независимый прогон или человек.

**Порог повторной обработки:** score ≥ 42 → ещё один цикл правки.

## Self-audit loop (обязателен при score ≥ 41)

### Pass 1: Черновик
- Применить все найденные паттерны
- Инжектировать живую речь (см. «Оживление» ниже)
- Получить черновик

### Pass 2: Самодопрос
- Прочитать свой черновик и честно ответить: «Что ещё выдаёт в нём ИИ?»
- Выписать каждый оставшийся признак в маркеры с ID паттерна
- Пересчитать score

### Pass 3: Финальная правка
- Устранить каждый признак из Pass 2
- Пересчитать score
- score < 42 → отдать финал
- score ≥ 42 и прогонов < 3 → вернуться к Pass 2
- прогонов ≥ 3 → отдать финал с пометкой об остаточных признаках

## Оживление текста (Soul Injection)

Паттерны убирают следы ИИ, но чистый текст без голоса всё ещё читается как машинный. Добавляй точечно, по жанру:

1. **Конкретика.** Числа, даты, имена, пути: «упало с 900 мс до 40 мс» вместо «улучшилась производительность».
2. **Мнение.** Реагируй, а не докладывай: «этот подход раздражает» вместо «подход имеет ограничения».
3. **Ритм.** Короткое предложение, потом длинное. Фрагменты допустимы.
4. **Первое лицо.** «Я», «мы», когда это естественно для жанра.
5. **Честная неопределённость.** «не уверен, но…» вместо гладкой уверенности на ровном уровне.
6. **Отсылки и самокоррекция.** «помните тот API, который я назвал проблемным?» — сигнал живого мышления.
7. **Не заканчивать каждый абзац выводом.** Иногда можно просто остановиться.

## Проверка галлюцинированных источников

Если текст ссылается на исследования, статьи или PMID — не оставляй непроверенные ссылки:
1. Проверить PMID через NCBI E-utilities (`https://eutils.ncbi.nlm.nih.gov/entrez/eutils/esummary.fcgi?db=pubmed&id=<PMID>&retmode=json`).
2. Если PMID не существует или не соответствует цитате — удалить ссылку, оставить утверждение в общей формулировке или заменить реальным источником.
3. Сфабрикованные PMID часто переиспользуются в нескольких статьях под разными журналами — искать повторы.
4. Цифры «Журнал (год)» без PMID — проверить поиском или убрать год/цифру, оставив «по данным литературы».

## Отчёт после правки

После прогона скилл выводит:
- список найденных паттернов (ID + цитата + правка);
- AI-tell score до и после;
- число итераций self-audit loop (например, «сошлось за 2 прогона»);
- краткое описание внесённых изменений.
